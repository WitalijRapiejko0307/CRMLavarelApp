# Очередь не обрабатывалась — заявки SalesRender перестали обновляться

**Дата:** 25.11.2026  
**Статус:** done (код); на проде нужно снять залипший мьютекс — см. «Действия на проде»  
**Контекст:** У клиента отказ по токену SalesRender (права). КЦ обновил права, после этого заявки (статусы, комментарии) перестали подтягиваться из SalesRender. Пример: заказ SR `383478`, комментарий `25.11ндст` не попал в CRM.

## Причина

Не права токена, а остановившаяся очередь.

1. Воркер очереди запускается планировщиком: `queue:work --stop-when-empty --tries=3`, каждую минуту, `withoutOverlapping()` ([`Kernel.php`](../../app/Console/Kernel.php)). Очередь — `database`, отдельного демона нет.
2. Около 02:30 (Europe/Minsk) 25.11 один запуск воркера завис/был убит и не снял мьютекс. У `withoutOverlapping()` без аргумента мьютекс живёт 24 часа.
3. Пока мьютекс «занят», планировщик каждую минуту пропускает запуск воркера. Задачи из очереди не выполняются.
4. `SyncSalesRenderJob` ставится в очередь каждые 5 минут на каждого клиента и копился: на момент проверки в `jobs` — 833 `SyncSalesRenderJob` и 6 `UpdateTrackingJob`, самая старая задача создана ≈ 02:35.

## Как подтверждено

| Проверка | Результат |
|----------|-----------|
| `laravel-2026-11-25.log` | `SyncSalesRenderJob` шёл каждые 5 мин с 00:01 до 02:26:08, далее ни одной строки до конца лога (12:49); вебхуки и `sendOrder` работали |
| До 02:26 чтение заказов | Ошибок `ordersFetcher` нет, итог `updated:0, skipped:13, failures:0` — права чтению не мешали |
| cron | `* * * * * php artisan schedule:run` есть, `dispatch-salesrender` в расписании |
| `jobs` | 832–839 задач, `min(created_at)` = 1795563302 ≈ 25.11 02:35 Минск |
| Мьютекс | `Cache::has('framework/schedule-'.sha1(...queue:work...))` → `MUTEX HELD` |
| `failed_jobs` | 4 записи, все от июля — ночных ошибок задач нет |

Ответ SalesRender по заказу `383478` (запрос с токеном КЦ) показал, что токен читает заказ; запрещено лишь поле `Project.name`, которое наш запрос `ordersFetcher` не запрашивает ([`SalesRenderService.php`](../../app/Services/SalesRenderService.php)).

## Что не установлено

Что именно повесило воркер около 02:30. В `laravel-2026-11-25.log` вокруг 02:26–02:52 записей нет, ошибок задач в `failed_jobs` нет. Логи за 24.11 не анализировались.

## Исправление в коде

[`app/Console/Kernel.php`](../../app/Console/Kernel.php):

```php
$schedule->command('queue:work --stop-when-empty --tries=3 --max-time=240')
    ->everyMinute()
    ->withoutOverlapping(10);
```

- `withoutOverlapping(10)` — мьютекс истекает через 10 минут вместо 24 часов: убитый/зависший воркер блокирует очередь максимум на 10 минут.
- `--max-time=240` — здоровый воркер сам завершается через 4 минуты, задолго до истечения мьютекса.

## Действия на проде

Код не снимает уже висящий мьютекс. После деплоя:

```bash
cd ~/crm && php artisan schedule:clear-cache
```

Воркер стартует в течение минуты и разберёт накопленные задачи. 833 `SyncSalesRenderJob` — это дубли по клиентам (≈ 130 пропущенных циклов), выполнятся подряд, каждый тянет актуальное состояние SR; первый же цикл обновит заказ `383478`.

Проверка после: количество `jobs` падает, в логе снова `SyncSalesRenderJob: checking ... / done`.
