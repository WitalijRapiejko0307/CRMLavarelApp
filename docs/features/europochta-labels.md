# Европочта: приоритетная служба, поиск ОПС, печать ярлыков

**Статус:** implemented (24.11.2026). Отличия от плана: ярлыки скачиваются последовательно (без `Http::pool`), пакетная стратегия `EVROPOST_LABEL_STRATEGY=batch` не реализована (собираем данные пробой), подсветка заявок без выбранного отделения показана на `/europochta`.
**Контекст:** API Европочты 1.9.0 (`docs/API Интеграции Европочта 1.9.0 (2) (1).docx`). Всё, что связано с Европочтой в этой постановке, работает только при `ep_api_version = new`. Для legacy JWT API ничего не меняется.

В постановку входят четыре независимых блока. Их можно выпускать по одному в порядке A → B → C → D.

| Блок | Что делает |
|---|---|
| A | Приоритетная служба доставки магазина (Белпочта или Европочта), подставляется в новые заявки |
| B | Поиск и выбор ОПС отправки в настройках (вместо ручного ввода ID) |
| C | Поиск ОПС получателя в заявке: проверка существующей реализации и доработки |
| D | Печать ярлыков Европочты: выбор заказов, скачивание, склейка, резервная выдача, логи |

## Блок A. Приоритетная служба доставки

### Решение
- Настройка уровня магазина `default_courier`: `belpost` (по умолчанию, если ключа нет) или `europochta`. Хранится в `TenantSetting`, миграций нет.
- В схеме настроек добавляется в группу «Магазин» (она открыта всегда): select «Служба доставки по умолчанию».
- Значение подставляется в новые заявки там, где `delivery_type` пустой: ручное создание, webhook, CSV-импорт. Явно указанный тип не перезаписывается. Существующие заявки не трогаем.

### Реализация
1. `Order::booted()` (`app/Models/Order.php:264`): в `creating`-hook вместо жёсткого `'belpost'` брать `TenantDefaults::courier($order->tenant_id)`.
2. Новый helper `app/Support/TenantDefaults.php`: `courier(int $tenantId): string`. Читает `TenantSetting::withoutGlobalScopes()` по `tenant_id` (так же, как `OrderController::epApiVersion`), кэширует на время запроса. Hook нельзя завязывать на `TenantSetting::get`, потому что в CSV и webhook текущий тенант определяется иначе.
3. Защита: если выбрана `europochta`, но Европочта не подключена (при `ep_api_version = new` пуст `token_ep`; при legacy пусты `login_name_ep`/`password_ep`), helper возвращает `belpost`. Иначе заявки будут уходить на службу, которую нельзя оформить.
4. `OrderController::create()` передаёт проп `default_courier`. `Orders/Create.vue`: `delivery_type: props.default_courier` вместо `'belpost'` (строка 424).
5. `TenantSettingController::schema()`: ключ `default_courier`, select `['belpost' => 'Белпочта', 'europochta' => 'Европочта']`, подсказка «Подставляется в новые заявки, если служба не указана. Европочта сработает, когда подключён её API».
6. Предупреждение в настройках: если выбрана Европочта, а токен не задан, показать подсказку под полем.

### Тесты
- Hook: нет настройки → `belpost`; `europochta` + токен → `europochta`; `europochta` без токена → `belpost`; явный тип не перезаписывается.
- Webhook и CSV без колонки доставки берут default магазина; чужой магазин не влияет.
- `OrderValidationTest::test_store_defaults_delivery_type_to_belpost` проходит без изменений.

## Блок B. ОПС отправки в настройках

### Решение
- Поле `warehouse_id_start` перестаёт быть текстовым: вместо ручного ввода показывается тот же поиск по справочнику ОПС, что и в заявке (мин. 2 символа, поиск по номеру и по тексту адреса, выбор из списка).
- Сохраняются `warehouse_id_start` (ID ОПС, как раньше, поэтому `createItemNew` не меняется) и `warehouse_label` (текст для показа, чтобы не искать название при каждой загрузке страницы).

### Реализация
1. `EvropostOfficePicker.vue` сейчас привязан к заявке (эмитит `city/street/building/opsId/europochtaStoreId`). Для настроек добавить режим `mode="settings"` (или тонкую обёртку): эмитит только `id` и `label`. Логику поиска и запрос `/api/europochta/stores/search` не менять.
2. `Settings/Index.vue`: новый тип поля `ops_picker`. Обработать во всех местах, где сейчас перечислены типы: инициализация `form` (стр. ~986), сборка `settings` при сохранении (стр. ~1180), отрисовка (после блока `select`, стр. ~521) и проверка изменений. `warehouse_label` объявляется как тип `hidden` (не отрисовывается, но попадает в сохранение).
3. `TenantSettingController::schema()`: `warehouse_id_start` → тип `ops_picker`, добавить `warehouse_label` (`hidden`). Оба ключа нужны в схеме, иначе `update()` их не сохранит (сохраняются только ключи схемы).
4. `TenantProvisioner`: добавить `'warehouse_label' => ''`.
5. Без токена Европочты справочник недоступен: picker показывает сообщение «Подключите Европочту», сохранённое значение остаётся видно.
6. Поддержка уже введённых вручную значений: если есть `warehouse_id_start`, но нет `warehouse_label`, показываем «ОПС {id}» и кнопку «Изменить».

### Ограничения, о которых надо знать
- `update()` не сохраняет пустые строки, поэтому очистить ОПС отправки из интерфейса нельзя, только заменить. Это существующее поведение всех полей, меняем его только если потребуется отдельно.
- Справочник `stores?type=1` содержит ОПС для приёма заказов получателем. Подходит ли тот же ID как `store_id_start` (точка отправки), по документации однозначно не следует. Проверяем на первом реальном магазине; поле остаётся совместимым с ручным значением.
- Кэш справочника общий на весь инстанс (24 часа, ключ `europochta:stores:type1`), токен берётся у первого магазина, у которого он был при загрузке кэша. Приемлемо, оставляем.

### Тесты
- Settings сохраняют оба ключа; `SettingsAccessTest` проходит.
- `EvropostStoreSearchTest` проходит без изменений.

## Блок C. ОПС получателя в заявке

Основа уже есть и работает: `EvropostOfficePicker` подключён в `Orders/Create.vue` и `Orders/Show.vue`, `europochta_store_id` хранится в заявке и в карточке клиента, `createItemNew` использует выбранный ID и пропускает нечёткий поиск.

Доработки:
1. Сверить логику поиска со скринами: «Три» должен находить и «Тринити», и «Петриков» (поиск по подстроке во всём адресе). Если `filterByText` ищет только с начала слова, привести к подстроке.
2. На `/europochta` помечать заявки без `europochta_store_id` («Отделение не выбрано») и не оформлять их нечётким поиском по адресу молча. Нечёткий поиск остаётся запасным путём, но результат помечается в ответе. Это изменение `index()` (добавить поле в `eligibleOrders`) и `Create.vue`, `createItemNew` не меняется.
3. При смене доставки на Европочту в заявке поле поиска появляется, ID сохраняется. Сквозной сценарий закрепляется тестом.

### C2. ОПС отправки в заявке (по аналогии с кабинетом Европочты)

В заявке с доставкой Европочта остаются ровно два поля адреса: **ОПС отправки** и **ОПС получателя**. Поля «Корпус» и «Квартира» для Европочты убираются (сейчас они показаны под picker'ом в `Orders/Create.vue` и `Show.vue`).

Правила:
- Если в настройках задан ОПС отправки (блок B), он подставляется в заявку автоматически. Пользователь может заменить его в этой заявке.
- Если в настройках ОПС отправки не задан, пользователь выбирает его в заявке сам.
- Выбор действует только для этой заявки: в настройки магазина и в карточку клиента он не записывается.
- При создании отправления: ОПС отправки из заявки, а если его нет, то из настроек (`warehouse_id_start`). Если нет ни там, ни там, ошибка `config_error`, как сейчас.

Реализация:
1. Миграция: в `orders` добавить `europochta_store_start_id` (nullable integer) и `europochta_store_start_label` (nullable string). Добавить в `Order::$fillable` (`Order.php:115`) и `$casts`.
2. `OrderController`: правила валидации рядом с `europochta_store_id` (стр. ~117, ~491, список полей ~506). Поля принимаются только для `delivery_type = europochta` (при смене типа сбрасываются, как `europochta_store_id` на стр. ~816).
3. `create()` и `show()` передают в форму ОПС отправки из настроек (`warehouse_id_start` и `warehouse_label`).
4. `Create.vue`/`Show.vue`: для Европочты два блока `EvropostOfficePicker` (режим `settings`): «ОПС отправки» и «ОПС получателя»; в `watch` на `delivery_type` сбрасывать новое поле при уходе с Европочты.
5. `EvropostService::createItemNew`: `store_id_start` = `$order->europochta_store_start_id` ?? `warehouse_id_start`. `createItem` (legacy) не меняется.
6. `CustomerService::DELIVERY_FIELDS` и `OrderObserver::PROFILE_ATTRIBUTES` не расширяем: ОПС отправки в профиль клиента не попадает.
7. Страница `/europochta`: в таблице показывать ОПС отправки заявки (из заявки или из настроек), чтобы оператор видел, откуда уйдёт посылка.

Тесты: подстановка из настроек; замена в заявке не меняет настройки и карточку клиента; `createItemNew` берёт `store_id_start` из заявки, иначе из настроек; при смене типа доставки поле сбрасывается; `EvropostCreateItemNewPayloadTest` проходит без изменений.

## Блок D. Печать ярлыков

### Принятые решения

| Вопрос | Решение |
|---|---|
| Как получаем PDF | Рабочий путь: одиночные `GET /api/external/label/address/{n}` и `/label/thermal/{n}`. |
| Склейка | Один PDF из страниц одиночных ответов. Размер каждой страницы сохраняется: 1 ярлык = 1 страница, без раскладки на A4. Используется одна служба склейки: FPDI. |
| Пакетные методы | Для пользователя не используются. Их формат в документации не описан. Скрытая проба собирает метаданные (см. «Логи»). |
| Если склейка не удалась | Пользователь получает скачанные ярлыки без склейки (см. «Резервная выдача»). |
| Формат по умолчанию | Обычный ярлык: адресный A5 (`a5`). Термоярлык 10×10 (`thermal`) выбирается вручную. |
| Где выбор формата | На `/europochta` рядом с кнопкой скачивания, запоминается для магазина (ключ `ep_label_format`, в схему настроек не входит). |
| Какие заказы печатаются | Статус «Оформлен», `delivery_type = europochta`, непустой трек. Проверка на сервере. |
| Секция «Оформлены» | Окно 10 строк, дальше прокрутка; выборка до 200 заказов за 30 дней; заказ исчезает при уходе из «Оформлен». |

### Загрузка (EvropostService)

- `newApiBinaryRequest(string $path, string $token)`: отдельный метод, `newApiRequest` не трогаем (он вызывает `$response->json()` и портит бинарный ответ). Возвращает `status`, сырое `body`, `content_type`, `elapsed_ms`.
- `fetchLabel($track, $format, $token)`: успех = 200 и тело начинается с `%PDF`. 401 → `auth_error`, 404 и 400 → `label_unavailable`, остальное → `api_error`. Один повтор при сетевой ошибке или 5xx.
- `fetchLabels($orders, $format)`: пачки по 5 через `Http::pool`. Возвращает `['pdfs' => [трек => binary], 'errors' => [трек => сообщение]]`.
- Токен: `TenantSetting::get('token_ep')`, как в `createItemNew`.

### Склейка (EvropostLabelMerger)

- `merge(array $pdfBinaries): string`. Для каждой страницы: `getTemplateSize()` → `AddPage(orientation, [w, h])` → `useTemplate()`. Порядок = возрастание `id` заказа.
- При любой ошибке бросает исключение с типом и сообщением FPDI. Логи см. ниже. Запасной службы склейки нет: при ошибке срабатывает резервная выдача.

### Резервная выдача (EvropostLabelDelivery)

Пользователь всегда получает то, что удалось скачать. Порядок решений:

1. Скачаны все ярлыки, склейка прошла → один PDF `europost-labels-YYYYMMDD-HHMM.pdf`.
2. Склейка не удалась, скачано несколько отдельных PDF → ZIP `europost-labels-YYYYMMDD-HHMM.zip` с файлами `{трек}.pdf` (`ZipArchive`, он в проекте уже используется в `BelpostPartialReceiptOpisService`). Заголовок `X-Label-Merge: failed`.
3. Склейка не удалась, скачан один PDF → отдаётся этот PDF как есть.
4. Часть ярлыков скачать не удалось (404, 400, сеть) → выдаётся всё скачанное (по правилам 1–3), ошибки по трекам в заголовке `X-Label-Errors` (JSON, urlencode).
5. Не скачано ничего → 422 JSON со списком «трек — причина».
6. Задел на будущее: если стратегия загрузки переключена на пакетный метод (`EVROPOST_LABEL_STRATEGY=batch`, по умолчанию `single`), ответ пакета отдаётся клиенту без изменений с тем типом, который определён по первым байтам (`%PDF` → pdf, `PK` → zip). Если пакет не удался, автоматически идём одиночными запросами (пункты 1–5).

`Content-Type`/расширение определяются по реальным данным, а не по запросу.

### Контроллер и маршрут

`EvropostController::labels(Request)`:

- Валидация: `order_ids` (array, 1..50, integer), `format` (nullable, `in:a5,thermal`).
- Отбор: `Order::whereIn('id', ...)->where('status', 'Оформлен')->where('delivery_type', 'europochta')->whereNotNull('track_number')`. `TenantScope` отсекает чужих. Пропущенные заказы в запрос к Европочте не уходят, причины в `X-Label-Skipped`.
- Нет подходящих → 422. `ep_api_version = legacy` → 422. Нет `token_ep` → 422.
- Формат: из запроса, иначе `TenantSetting::get('ep_label_format', 'a5')`. Если пришёл `format`, он сохраняется через `TenantSetting::put`.
- `set_time_limit(120)`.
- Маршрут `POST /europochta/labels` внутри `europochta.*` (`tenant.type:store`). Контроллер уже подключает `tenant.writable`, поэтому read-only получает 403.

### Логи для разбора проблем (EvropostLabelLogger)

Канал `europost_labels` (`storage/logs/europost_labels-*.log`, 30 дней). Все записи одного запроса связаны `request_id`.

| Этап | Что пишем |
|---|---|
| `request` | `tenant_id`, формат, число выбранных / допущенных / пропущенных заказов, причины пропуска |
| `fetch` (на каждый трек) | HTTP-статус, `Content-Type`, размер, первые 8 байт, версия PDF (`%PDF-1.x`), время ответа, `seconds_since_created` (сколько прошло с оформления), текст ошибки |
| `merge` | входное число PDF, версии PDF по каждому, число страниц, размеры страниц, время; при ошибке класс исключения и сообщение (например ошибка чтения xref), индекс проблемного файла |
| `delivery` | какой вариант выдан (pdf / zip / single / raw), размер ответа, число ошибок |
| `probe` | метаданные ответа пакетного метода: статус, `Content-Type`, `Content-Length`, первые 8 байт, число страниц, тело 422 (`unprocessed`), время |

Правила:
- Содержимое PDF в обычные логи не пишется (там ФИО и телефоны получателей).
- Отладочные образцы: при ошибке склейки сохраняем проблемный исходный PDF в `storage/app/europost-label-debug/{request_id}/` (не публичный диск, не в git). Не более 5 образцов на магазин в сутки, включается `EVROPOST_LABEL_DEBUG_SAVE` (по умолчанию включено только для сбоев склейки). Ежедневная задача в `Kernel` удаляет образцы старше 14 дней.
- Скрытая проба (`EvropostLabelProbe`): выполняется после формирования ответа (`app()->terminating()`), не влияет на ответ пользователя, исключения проглатываются. Один `POST /label/thermals` или `/label/addresses` с теми же треками. Не чаще раза в минуту на магазин (`Cache::add`), отключается `EVROPOST_LABEL_PROBE=false`. Содержимое ответа не сохраняется, только метаданные из таблицы выше.

### Фронтенд (Create.vue)

Очередь «Отправить», кнопки «Оформить» и `PackingChecklist` не меняются.

- Секция «Оформлены» стоит вне блока `v-if="orderQueue.length === 0"` / `v-else`: иначе она исчезнет сразу после оформления всех заявок.
- Окно 10 строк с прокруткой и закреплённой шапкой. Столбцы: чекбокс, клиент, адрес отделения, трек, дата оформления. «Выбрать все» и счётчик. Только что оформленные заказы появляются в списке, но не отмечены.
- Селект формата «Обычный ярлык (A5)» / «Термоярлык 10×10» (значение из `labelFormat`).
- Кнопка «Скачать ярлыки (N)»: `apiDownload('/europochta/labels', 'POST', { order_ids, format }, ['application/pdf', 'application/zip'], 'europost-labels.pdf')`. Имя файла берётся из `Content-Disposition`.
- Больше 50 выбранных → скачивание частями.
- Если пришёл `X-Label-Merge: failed`, показать нейтральное сообщение «Ярлыки скачаны отдельными файлами в архиве». Если пришёл `X-Label-Errors`, показать список треков с ошибкой.
- После оформления: `router.reload({ only: ['registeredOrders'] })`. Ответ `register` не содержит данных заказа.
- При `epApiVersion === 'legacy'` и `readOnly` секция скрыта или заблокирована.

`apiDownload` уже принимает список допустимых типов (`acceptTypes`), поэтому ZIP-ответ он пропустит без изменений в `utils/api.js`. Функция `saveBlob` сейчас локальная в `Belpost/Batch.vue`: либо дублируем минимально, либо выносим в общий helper (тогда `Batch.vue` меняется только импортом).

## Риски до первого реального запуска

- Ярлык может быть недоступен сразу после оформления. Решение примем по логу `fetch` (`seconds_since_created`).
- Бесплатный FPDI может не прочитать PDF Европочты (сжатые xref, версия 1.5+). Пользователь в этом случае получает ZIP, а в логе остаются версия PDF, ошибка и образец файла. По этим данным решаем, чем заменить склейку.
- Формат ответа пакетного метода станет известен из лога пробы.
- Подходит ли ID из справочника ОПС как точка отправки (`store_id_start`), проверяется на первом реальном магазине (блок B).
